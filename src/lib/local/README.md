# 本地额度汇总

`codexQuotaSummary.js` 计算所有启用 Codex OAuth 账号的普通额度。
共享账号按套餐分组，绑定专用 API Key 的账号各自独立，不计入共享额度。
旧版单 Key 绑定及停用、已删除 Key 的绑定仍视为专用，直到主动清空绑定。
配额跟踪器分别展示共享汇总与专用账号额度、绑定人员，并支持按额度归属跨分页筛选。
页面按实际额度周期展示汇总，5 小时与每周分别计算。
Codex 的 primary/secondary 顺序不代表周期，按返回的窗口秒数归类。
仅有周额度的账号将 5 小时额度指向同一份周额度，并标注共用；两项均正常汇总。
共用额度只发一次周告警，不生成缺项提示。
显示百分比和同套餐满额账号的等效数量，不将百分比换算为 Token 或请求数。
缺失、非法或过期数据标记为未知，不视作满额或耗尽。

`loadCodexQuotaSummary.js` 与本地路由复用额度缓存及同时发生的查询，覆盖所有账号分页。
配额页通过独立组件和 `/api/usage/codex-summary` 读取汇总。
`alerts/codexQuota.js` 使用相同汇总结果，按周期独立判断告警；该周期数据完整且剩余达到阈值才发。
两个周期同时触发时合并一条通知，已提醒的周期独立去重，新触发的周期仍可提醒。
汇总保留各周期的有效重置时间，告警按北京时间显示；共享账号时间不一致时显示最早、最晚时间。
缺失或无效的重置时间标为未知，部分账号缺失时注明已知范围及未知账号数量，不推算恢复时间。
`wecomAlerts.codexQuotaMode` 默认 `account`，手动选择 `total` 后启用总额度告警。
后台每五分钟检查；共享额度耗尽、低额度分别按套餐和周期每天最多提醒一次，
专用额度按账号、周期和状态独立去重，未知专用账号不影响共享池告警。
专用账号的额度告警使用绑定 API Key 的名称作为企业微信 UserID，通过 `mentioned_list`
提醒全部绑定人员（包括停用但仍绑定的 Key），正文同时显示 `@名称`；重复 UserID 合并，已删除 Key 不猜测接收人。
共享额度告警不携带专用人员的 @ 列表。上游 402 的专用账号告警不受总额度模式屏蔽。
启用低额度模型自动切换时，Codex 额度告警附上已保存的目标模型、阈值及生效条件；关闭时不显示。
该说明表示当前切换规则，实际请求仍受剩余额度、模型权限及账号可用性约束。
凭证异常、账号到期和其他提供商仍沿用原有逻辑，发布不修改已保存配置。

告警配置与测试推送遵循面板的 `requireLogin` 设置；关闭登录时可直接配置，
开启登录或设置读取失败时需要有效的面板登录凭证。

模型切换沿用已保存的开关、阈值和目标模型。单个账号的 5 小时用量达到阈值，
只切换该账号；只有周额度的账号使用共用窗口。5 小时或每周总用量达到阈值，
所有可用账号后续请求切换，额度恢复后使用原请求模型。
不同套餐分别计算，全局切换要求该周期所有适用套餐均达到阈值。
账号分配参考周期只影响账号排序，不改变上述模型切换规则。
