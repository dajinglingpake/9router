# 本地请求策略

本地 API 路由从本目录导入聊天和认证入口。`src/sse/handlers/chat.js` 和
`src/sse/services/auth.js` 保留上游实现，便于后续合并。

- `chat.js`：请求解码、API Key 校验和进入账号调度前的短期排队。
- API Key 模型和组合白名单复用上游 `services/keyAccess.js`，在本地聊天入口、组合展开前校验；额度降级模型也必须在白名单内，否则继续使用原模型。
- `modelRouting.js`：组合的账号专属模型、会话绑定、并发队列、冷却重试和流结束释放。
- `requestContext.js`：请求标识、调用方归属和并发监控元数据。
- `accountSelection.js`：按容量选择账号、选择预占和会话账号绑定。
- `apiKeyRouting.js`：按提供商和 API Key 身份持久化固定账号，不存储原始 Key。
- `../services/accountApiKeyAccess.js`：独占账号池筛选，供聊天及其他推理接口共用。
- `accountHealth.js`：账号过载冷却、模型锁和成功后的健康状态恢复。
- `auth.js`：组合上述账号策略，复用上游 API Key 提取逻辑。
- `routingPolicy.js`：独立的 Codex 路由设置及默认值，不修改上游设置默认值。
- `accountBalancing.js`：新会话按负载选择账号，同负载轮询；旧会话保持绑定。
- `accountLoad.js`：统计账号在途请求，包括不限并发的账号，流结束或取消时释放。
- `quotaPriority.js`：新会话在空闲账号或全忙账号中按有效额度排序，同额度轮询。
- `quotaRouting.js`：额度缓存、按额度池锁定、低额度切换模型和额度耗尽后的迁移判断。
- `comboRouting.js`：复用上游组合轮询、能力选择与失败回退。

智能组合复用上游 System One 决策及会话策略，会话标识按调用方隔离，决策账号同样遵守专用 API Key 绑定。
普通聊天传递已配置的自定义系统提示词；账号试用保持原有测试提示词，不注入该配置。

在「设置 → Codex 账号路由」配置按 API Key 固定账号、分配策略、额度耗尽迁移、低额度模型及阈值。
未配置时沿用原有账号分配策略，API Key 固定账号、额度耗尽迁移和低额度模型切换默认关闭。
只有手动配置并保存后，新策略才生效；部署不写入或覆盖实例数据库中的配置。
负载均衡和轮询优先选择没有在途请求、没有排队请求的空闲账号；
同等条件轮询，避免回到仍忙碌的首个账号。账号全部忙碌时按所选策略分配。
已有会话继续使用原账号；不限并发也参与忙闲判断。
启用「按 API Key 固定账号」后，同 Key 的所有 Codex 会话（含无会话 ID 的请求）共用一个账号，
优先于会话绑定。只在首次请求到达时分配，优先选择未绑定其他 Key 的可用账号；
全部可用账号已被分配后，优先选择绑定 Key 最少的账号，再按负载和所选策略分配。
停用或删除的 API Key 不计入绑定数量。账号停用、删除或确认额度耗尽时重新分配；
额度迁移不受会话迁移开关影响，繁忙、冷却、过载、普通限流和网络失败不触发换号。
绑定保存在实例数据库，重启仍保留；切换后不自动回到原账号。关闭该功能恢复会话策略，
已访问的会话保留最近使用的账号；无 API Key 的请求一直沿用会话策略。
在「提供商 → 账号 → Edit → 专用 API Key（可多选）」可将一个账号绑定给多个 Key 专用。
绑定保存为账号的 `exclusiveApiKeyIds`，仅存 Key ID，无需修改数据库结构；兼容旧单 Key 配置。
名单内的 Key 在此提供商下始终使用该账号，其他 Key 和无 Key 请求仅使用共享账号。
同一 Key 在同一提供商下只能绑定一个专用账号，事务内检查冲突，防止并发配置产生歧义。
禁用账号时仍可配置绑定，保存不会自动启用账号；手动启用后按绑定名单接收请求。
账号停用、冷却、额度耗尽或重试不会使这些 Key 切换账号或回退到共享池。
旧会话绑定、API Key 自动绑定和指定账号均受独占筛选约束；
聊天排队结束后再次检查账号归属。停用或删除 Key 不会自动公开专用账号，
需要手动清空绑定以恢复共享，或重新绑定。提供商账号列表及「配额跟踪」显示全部绑定人名称，
Key 停用或删除后显示对应状态。设置变更不取消已经发送到上游的请求。
Codex 账号可在提供商账号列表或「配额跟踪」点击「重新登录」，复用现有授权弹窗，
支持自动回调、手动粘贴回调地址及网站 Token。凭证保存逻辑独立位于
`src/lib/oauth/reloginCodex.js`，更新指定账号，不创建替代账号。
保存前核对原账号邮箱和 ChatGPT 账号/工作空间 ID；误登其他账号、授权失败或账号已删除时不覆盖原凭证。
重新登录保留账号名称、专用 Key 绑定、并发、代理、间隔、冷却配置和启用状态，
清除旧凭证相关的错误及模型锁。禁用账号仍保持禁用，需手动开启后才能接收请求。
绑定账号被手动停用或删除时，在下一次请求中选择可用账号重新绑定；
替代账号仍须通过冷却、额度和模型启用筛选。排队期间停用也会在访问上游前重新分配。
手动选择「额度优先」时，新会话先选空闲账号中剩余额度最高的；
如果全部账号忙碌，则在全部可用账号中选额度最高的，即使该账号需排队。
额度相同轮询。默认以 5 小时和每周额度中较低的剩余比例比较，也可选择单一周期。
未知额度不视作满额；同一忙闲组内优先比较有效额度，全部未知时轮询。
该策略独立启用额度查询，不要求开启模型降级或额度耗尽迁移。
启用低额度模型切换后，普通 Codex 5 小时或每周额度已用达到 90% 时，
后续请求使用同账号的 `gpt-6-luna`。额度恢复后回到客户端请求的模型。
降级模型须存在于模型注册表，并符合账号模型启用列表和上下文标记。
审查和 Spark 按各自额度池判断耗尽，不自动降级到普通 Luna。

仅在 API Key 固定账号、额度优先策略或额度相关开关启用时查询额度并记录额度池锁，全部关闭时保留原有错误处理。
额度查询缓存一分钟并合并同时发生的查询，不依赖打开额度页面；
首次查询和过期刷新在账号选择锁外执行，失败时不沿用旧额度。
确认额度耗尽才迁移绑定，普通 429 限流和 503 过载仍保持原账号。
耗尽锁按额度池记录上游实际恢复时间，迁移重试先释放旧并发槽位。

请求转换、OAuth 刷新和 Codex 请求格式继续由 `open-sse` 上游模块负责。
流量及完成状态监控放在 `open-sse/utils/localStreamMonitor.js`，流处理只保留调用点。
本地模型能力补充放在 `open-sse/providers/localCapabilities.js`，上游同名定义优先。
使用情况与告警共用 `src/lib/providerUsage.js` 的额度查询及凭证刷新逻辑。

合并上游后，检查新增 API 路由是否导入本地入口；将上游新增的请求选项和账号筛选条件
同步到本地调度调用点，不复制 Codex 执行器或翻译器。模型启用列表筛选同时检查
账号专属模型与 `[1m]` 上下文标记。

本地策略与凭证更新通过隔离数据库测试及隔离实例验证，不使用实际账号执行测试登录。
关键绑定、重新登录及上游 Codex 请求格式和流式完成行为可运行：

```bash
cd tests
./node_modules/.bin/vitest run unit/account-api-key-bindings.test.js unit/codex-relogin.test.js unit/codex-gpt6-lite.test.js unit/openai-responses-completion-watchdog.test.js unit/v1-models-combo-context.test.js --maxWorkers=4
```
