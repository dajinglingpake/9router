# 独立账号申诉

请求诊断的账号测试卡片提供「申诉」入口。点击后在 9router 新页面中操作独立的 OpenAI 帮助中心浏览器，可自行填写和发送客服消息；系统不会自动发送申诉。

- 使用该账号已有的 Codex 授权，由隔离浏览器向官方客服身份接口核对账号邮箱，再打开客服对话。
- 浏览器在 9router 容器内按需启动，使用独立的临时用户目录和账号代理，不读取用户日常浏览器的 Cookie。
- 页面和客服账号令牌仅在服务端浏览器内使用，不将令牌返回给 9router 前端，也不将令牌放入 URL 或日志。
- 账号禁用状态不影响申诉。页面提供账号启用/禁用和标签备注编辑，使用现有账号接口保存，与请求诊断中的账号信息一致；打开申诉页不会自动修改账号状态或标签。
- 每个申诉窗口使用独立进程和用户目录，最多同时运行两个窗口。关闭窗口后结束进程组并清理临时目录；连接中断一分钟或十五分钟无操作也会回收。
- 文案输入框预填默认申诉内容，可自由修改，重新连接申诉窗口时保留修改。点击「填入客服输入框」只填写内容，需用户在帮助中心内自行点击发送。网站出现人工验证时，由用户在窗口内完成。
- 自动保存已登录账号在客服窗口收到的对话消息，包括流式回复和打开的历史对话；输入框草稿、请求头和令牌不会写入记录。对话保存在现有数据库的独立 `accountAppealThreads` / `accountAppealMessages` KV 命名空间，无需修改数据库结构。
- 请求诊断的账号卡片展示最近回复或结果备注，点击「申诉记录」可查看完整对话并补充处理结果。关闭申诉窗口、重启容器后记录仍保留。关闭期间收到的新回复，需重新打开相应客服对话后同步；不会在后台常驻浏览器轮询。
- 附件只记录名称，不下载文件。单条消息超过 100,000 个字符时保留前 100,000 个字符并显示截断提示。消息按账号、客服会话和消息 ID 去重，不会因重复加载覆盖手工处理结果。

## 构建

在现有 Debian 9router 镜像上增加浏览器层，不修改上游 Dockerfile：

```sh
docker build -f "local/account-appeals/Dockerfile" \
  --build-arg "ROUTER_IMAGE=9router:your-current-image" \
  -t "9router:with-account-appeals" "."
```

容器必须启用 `init: true`，用于回收浏览器子进程。Chromium 在 Xvfb 图形环境中运行，使用 DevTools 管道通信，不监听调试 TCP 端口。浏览器和图形环境一起启动、回收；网站人工验证仍须用户自行完成。针对现有群晖内核，浏览器在容器内使用无 Chromium 沙箱模式。

本地开发可设置 `ACCOUNT_APPEAL_CHROMIUM` 指向 Chromium/Chrome 可执行文件。浏览器支持 HTTP、HTTPS 和无认证 SOCKS5 代理；网页中继代理不适用。

## 实现边界

现有令牌已验证可调用 `support.api.openai.com/api/v1/me` 和客服接口。界面通过帮助中心当前提供的全局上下文更新函数接入身份，仅建立当前帮助中心页面的客服会话，不生成 ChatGPT 网页登录 Cookie。帮助中心内部页面结构更新可能需要同步调整适配代码；身份不匹配时停止登录。

账号会话、截图和操作接口遵循 9router 现有登录设置，并按当前管理会话隔离。免登录模式使用独立的随机 HttpOnly 会话 Cookie 区分访问者；开启登录要求后仍须有效登录。控制接口只接受有限的点击、滚动、键盘和填写操作，不提供任意 URL 导航、脚本执行或调试连接。
